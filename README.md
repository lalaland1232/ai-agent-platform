# AI Agent Platform

A backend platform that lets users create custom AI agents and use them to perform tasks — built with FastAPI, SQLAlchemy, PostgreSQL, and integrated with an LLM via OpenRouter.

> **Status: In Progress.** Core agent creation, authentication, and AI integration are working. Conversation sessions, message history, and multi-step agent execution are planned next.

## What It Does

Users sign up, authenticate, and create their own AI agents — each with a name, a defined task ("work"), and a system prompt automatically generated by an LLM based on the agent's purpose. Once created, users can invoke their agent to perform its task, with the platform handling the full request lifecycle: authentication, ownership verification, prompt retrieval, and response generation.

This mirrors the core idea behind enterprise agentic AI platforms — a system where users define an agent's purpose once, then reuse it to complete tasks on demand.

## Architecture

```
Client Request
      │
      ▼
   FastAPI Route  ──▶  Depends() Auth (JWT)
      │
      ▼
   Service Layer   (business logic, orchestration)
      │
      ├──▶  Repository Layer   (database access)
      │
      └──▶  AI Service (ChatGpt)  ──▶  OpenRouter API (LLM)
```

The project follows a **Route → Service → Repository** architecture, consistent across every module — authentication (signup, login, refresh) and the agent module itself.

### Design Decisions

**AI Service is abstracted behind a contract, not hardcoded.**
`AgentService` depends on an abstract `AI` base class (`generate_response`), not directly on `ChatGpt` or OpenRouter. This means the LLM provider can be swapped — a different model, a different API, even a local model — without touching `AgentService` or any route logic. This follows the same Dependency Inversion principle applied throughout the codebase.

**Agent creation generates its own prompt via the LLM.**
Instead of asking users to write a system prompt themselves, `create_agent` sends the agent's declared purpose, input format, and output format to the LLM, which generates a tailored prompt. That prompt is then stored and reused every time the agent is invoked — the LLM is used once at creation time, not on every single call, keeping repeated usage fast and consistent.

**Ownership is enforced at the service layer.**
Every agent action checks `agent.user_id == current_user.user_id` before allowing access, returning proper `403`/`404` responses rather than silently failing or leaking data across users.

**Authentication reused from a prior project.**
Signup, login, JWT access/refresh token flow, and session tracking (with device/IP logging and revocation) were carried over from an existing, tested implementation rather than rebuilt from scratch — allowing focus to stay on the new agent-creation logic.

## Tech Stack

- **Framework:** FastAPI
- **Database:** PostgreSQL, SQLAlchemy ORM
- **Migrations:** Alembic
- **Auth:** JWT (access + refresh tokens), bcrypt password hashing
- **AI Integration:** OpenRouter API
- **Containerization:** Docker, Docker Compose

## Core Entities

| Table | Purpose |
|---|---|
| `User` | Registered platform users |
| `Session` | Refresh token tracking per login (device, IP, revocation) |
| `Agent` | User-created AI agents — name, task, generated system prompt |
| `Artifact` | Stored user artifact (e.g. verification image) |

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/signup` | Register a new user |
| `POST` | `/login` | Authenticate and receive access/refresh tokens |
| `POST` | `/refresh` | Rotate refresh token, issue new access token |
| `POST` | `/create_agent` | Create a new agent (LLM generates its system prompt) |
| `POST` | `/agent/{agent_id}` | Invoke an agent with a task input |
| `GET` | `/agents_by_user` | List all agents owned by the current user |

## Running Locally

```bash
# Clone the repo
git clone https://github.com/lalaland1232/ai-agent-platform.git
cd ai-agent-platform

# Set environment variables
cp .env.example .env   # fill in DATABASE_URL, SECRET_KEY, API_KEY (OpenRouter)

# Run with Docker Compose
docker-compose up --build

# Or run locally
pip install -r requirements.txt
alembic upgrade head
uvicorn main:app --reload
```
